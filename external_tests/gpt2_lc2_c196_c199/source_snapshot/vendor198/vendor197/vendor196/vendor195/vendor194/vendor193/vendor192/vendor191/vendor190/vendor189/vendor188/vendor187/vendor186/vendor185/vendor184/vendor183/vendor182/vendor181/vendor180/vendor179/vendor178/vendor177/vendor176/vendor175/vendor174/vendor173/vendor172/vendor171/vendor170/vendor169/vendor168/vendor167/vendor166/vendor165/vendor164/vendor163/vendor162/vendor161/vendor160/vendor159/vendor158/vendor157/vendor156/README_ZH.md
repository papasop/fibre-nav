# C156：C155逐坐标精度轨迹只读审计

## 使用

将 `C156_CPU_LAUNCHER.py` 全文粘贴到 CPU Colab，提示时只上传 `C156_CPU_LAUNCHER_BUNDLE.zip`，无需解压。源码放在配套BUNDLE，不内嵌启动器。

只需要一份科学输入：C155原始结果总包，完整SHA256为 `5e52577034889cc7b5d0e0d77382d52a8dc87e0e608408f72de040ef5f14eb8b`。启动器挂载Drive后按 `INPUT_PINS.json` 精确定位；路径变化可填写 `C155_ZIP`。不会自动选择另一个同名或更新文件。

程序仅使用NumPy；不安装或加载Torch/HF、不加载GPT-2、不运行前向/反传。工作进程上限20分钟，自测另计。完成或失败都只封装一份结果ZIP，内含日志、报告、逐坐标数据、源码和结果清单，并尝试备份到Drive。

## 范围

固定C155原有七点和三个尺度（0、±1/4、±1/2、±1），全84个已暴露训练态的FP32原生/功能前向、两个预登记态的FP64记录，含所有零/+1复测。共核对1530条记录、588个封存float32点及七份完整系数张量。ID里含confirmation不代表未见状态。

原FP32验收门槛不变：响应 .002、KL .005、读裕度 .05、半径20及原1e-5舍入余量。安全损失仍使用 .0018/.0045/.075。FP64没有验收资格，也不从两个态构造全84态目标或通过率。

## 重算内容

- 重哈希C155原ZIP、全部结果成员和完整可信源码；不执行归档源码。
- 从C155内已保存的训练行、原始参数、共享基底、路由、写入头和控制量恢复冻结身份。逐一重算588个物理提交坐标及门槛、响应/读裕度/KL/半径损失和正则项。
- 核对全部1530条记录的顺序、态ID、路线、步长、坐标哈希与重复记录。重算原C155全部FP32目标、坐标诊断和两态精度诊断，并核对其摘要。
- 对全84态保留所有响应和读坐标的中心/正侧/负侧差分；两态额外比较FP32、FP64自身基线、FP64输出相对原FP32响应基线的逐坐标轨迹、响应损失、极值坐标、符号和铰链变化。
- 报告三个尺度之间的坐标斜率跨度、全部物理位移与float32提交余量。它们只是有限测点描述，没有新增“稳定”阈值或最优尺度选择。
- 从已保存的两套零图卡logits核对FP64响应基线及其相对原缓存FP32响应均值的偏移。原缓存FP32均值保持为归档参考，不用NumPy另一种求和顺序替换它。NumPy均值差异单独报告。
- 重算归档FP32聚合梯度的代数加权和及其对归档实际更新的点积；不重新求导。FP64有限差分也不代表FP64 AD验证。

恒定基线偏移在带符号坐标差分中抵消；经过绝对值、最大值和铰链后的响应损失可能变化。因此会同时保留两种参考，不能把参考切换当成精度改善。

## 输出与解释

主要文件：`REPORT_ZH.md`、`SUMMARY.json`、`ALL84_RECOMPUTED_COORDINATE_TRAJECTORIES.json`、`TWO_FOCUS_COORDINATE_PRECISION_ANALYSIS.json`、`ALL84_SEALED_POINT_DISPLACEMENT_AND_ROUNDING.json`、`BASELINE_REFERENCE_RECONSTRUCTION.json`、`ARCHIVED_GRADIENT_ARITHMETIC_ONLY.json`，以及重算的父诊断。

主摘要会打印两个态在FP32/FP64下三个尺度的响应坐标斜率跨度、比值、极值坐标、全部三个尺度的响应损失斜率和基线抵消误差，使下一次贴日志即可看到核心数据。比值不能认证精度优越性、导数准确性或因果来源。

只重开C155原包；十份前代原ZIP不会再次独立重哈希。FP64各端点完整logits没有归档，因此只能核对归档KL数值及相关算术，不能独立从logits重建端点KL。归档一致性也不证明模型测量准确性、时序、非访问、系统误差界、曲率界、收敛或可行性。

本地完整大小合成归档验证与真实科学数据审计分开记录于 `LOCAL_VALIDATION.json`。C156无训练、拟合、求解、Jacobian/SVD、选点、选头、部署、确认或排除输入。保留C155判定，LC2及单折仍开放。
