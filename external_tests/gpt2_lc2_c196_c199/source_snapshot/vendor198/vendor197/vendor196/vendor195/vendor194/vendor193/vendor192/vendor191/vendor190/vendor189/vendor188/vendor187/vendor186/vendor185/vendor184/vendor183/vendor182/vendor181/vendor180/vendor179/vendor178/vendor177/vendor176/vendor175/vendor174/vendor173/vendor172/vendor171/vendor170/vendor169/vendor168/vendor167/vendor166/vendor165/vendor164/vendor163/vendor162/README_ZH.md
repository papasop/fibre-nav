# C162：C161只读FP64训练审计（CPU）

本轮重算C161归档的8步系数更新、672条训练记录、84条最终FP64记录、336条原生FP32端点和168对原生重复。保留84态完整分母、原门槛和固定第8步判定，不选择中间头。

## 运行

1. 下载 `C162_CPU_LAUNCHER.py` 与 `C162_CPU_LAUNCHER_BUNDLE.zip`。
2. 将启动器内容粘贴到Colab代码单元运行。仅在提示时上传这个配套BUNDLE，不解压，不上传results.zip。
3. 挂载原Drive。程序按固定路径和SHA256定位C155–C161七个科学结果ZIP；如移动过文件，可填写相应输入绝对路径，不能修改哈希。
4. 使用CPU即可，无需GPU、Torch、HF依赖或模型下载。工作进程上限20分钟，自测另计。

## 核对与诊断

- 七个原始ZIP先核对整体哈希；可信读取器重新执行六个父包的归档绑定与既有算术核对。只执行配套BUNDLE内固定代码，不执行科学结果包内的源码。
- 独立重算完整84态的响应、读取、KL、半径与正则损失；按精确最大值并列规则聚合归档梯度。Adam使用独立标量实现核对符号、裁剪、偏差修正、动量、投影和8步链。
- 实际初始头和第8步最终头按字节绑定；重建840个NumPy连续映射绑定，核对168个实际保存的原生FP32提交点。
- 重算336条原生门槛，保留失败、救回与破坏态。输出全部84态×初始/最终×两轮的六坐标有符号响应裕度及FP64/原生FP32差异。
- 输出全部672条跨步损失变化、记录梯度与实际更新的点积、最坏态切换，以及每步全84态响应梯度的余弦关系。五个已知失败态仅作为回顾性阅读重点，其他态全部保留。

## 证据边界

归档梯度仍是记录输入，不验证真实导数。C161没有保存每次Torch FP64前向点的完整坐标，因此C162无法独立重哈希这些点，也无法重新测量其记录的NumPy/Torch映射误差。可验证的是保存的头与FP32点、可重建的NumPy点绑定，以及观测记录的算术一致性。

端点KL使用归档标量重算门槛及损失，没有模型logits重放，不能宣称独立验证KL测量。FP64与原生FP32差异同时涉及提交舍入、前向精度、归约和参考算术，不能据此单独认定物理误差来源。FP64响应分类是诊断，不是完整写入验收。

记录梯度的点积、余弦、最坏态切换和观察值减线性预测，均不是优化器因果解释、曲率界、收敛、可行或不可行证明。审计也不证明时序、非访问或泛化。准备态继承原归档，未重新制备。

C161固定最终头的判定保留；本轮没有训练、新状态、确认或排除输入评估，不选择候选，不闭合LC2。
