# C180：固定最终头的八步全响应坐标续训（CPU）

## 使用

在 Colab CPU 运行时运行配套 `C180_CPU_LAUNCHER.py`。提示时一次上传 **C180_CPU_LAUNCHER_BUNDLE.zip**，无需解压，也不需要另选 SOURCE.zip。科学结果ZIP不能代替配套BUNDLE。

挂载原 Google Drive 后，程序按固定路径及SHA256读取 C155–C179 共25个原始结果包。若文件移动，可在启动器 `INPUT_PATHS` 对应键填写本地绝对路径；内容仍须匹配原哈希。BUNDLE仅含启动和实验源码，不包含25个科学结果包或GPT-2模型权重。

成功或工作失败均封装一个结果总包，包含日志、摘要、逐态记录、封存点、更新证书与源码。自动下载并尝试备份至Drive，备份后比较SHA256。启动器在执行实验代码前验证配套BUNDLE的整体哈希及逐文件清单。

## 本轮目的与固定选择

根据供应日志，C178固定最终头在原生两轮均通过80/84态，仍有4态响应失败。C179归档审计保留该判定，并报告一个原生获救态的FP64响应仍为0.0020011258363865636，略高于0.002。这些是父实验报告；C180不会将它们预填为新的模型结果。

C180从原C178预定第8步最终头继续固定8步：不从恢复头、探针或中间检查点选择起点，也不在本轮选择最优头。初始头摘要固定为：

`e7cbfd1e636869ff34e7c08b235900b560af2bed8607ed9f056cf2b0297daadd`

先通过不可变C179检查器重新绑定25个原包，独立重建C178并核对原C179源码、完整摘要、上游绑定与所有重建算术和诊断产物，之后才加载模型。原C178最终头的原生两轮和首批FP64观测必须满足原重放容差与点身份。

## 训练与验收

- 同一GPT-2修订、LoRA-A、84个已暴露训练态、原始参考输出、V、路由和参数图不变；生产系数头形状为3×2×36。
- 每步重新测量全部84态的六个响应坐标梯度，以及响应损失和guard损失梯度。每步保留全部84×6×2＝1008条有符号LP约束，最多调用一次固定SciPy求解器。
- 固定步长0.001，固定8个更新槽。每次提交前检查方向和实际binary64头差的精确归档仿射证书。空活动集采用登记的零方向且不调用LP；证书未解决则保留部分工作并停止，不搜索步长、不回退或改选头。
- 训练响应上限仍是 `max(0.0018, 当前六坐标最大绝对响应)`；它不是新的原生验收阈值。Read、KL、半径和正则guard及其梯度继续记录，响应LP不保证这些guard在有限更新后保持。
- 仅预定本轮第8步最终头进行全部84态两轮原生完整门槛验收与最终FP64重复。响应0.002、KL、读裕度、更新半径、参考分布及其他门槛不变，所有失败保留。
- C176、C178和C180合计24个续训槽，从C170固定最终头之后计数，不包含C170自己的8槽。

历史ID含confirmation的态在本轮均是已经暴露的训练态，不是新确认态。

## 新增精度裕度报告

只使用已有初始/最终端点观测，比较84态×2个头×2轮原生测量，共336条记录，不增加模型前向。输出每态原生与FP64六坐标响应、最大绝对响应、距0.002的有符号裕度、响应门槛分歧，以及原生完整门槛状态。

`native_full_pass_and_FP64_response_pass`只是并列描述，不是新验收合同。FP64这里只报告响应门槛，不建立FP64完整验收；原生完整接受判据不变。精度差异不等于准确度界，也不能据此确定硬件误差原因。

## 资源与结果边界

CPU工作进程上限240分钟，自测、依赖安装和打包另计。完整科研工作计划2355次模型前向，其中1682次functional FP64前向；5376次标量反传；672个系数响应Jacobian块、4032行响应坐标梯度；最多8次LP；保存840个实际FP64点。求解器内部线性系统次数未知，记录null。仅子进程屏蔽GPU，保留笔记本内核的GPU环境。

本轮是显式使用离线Jacobian与LP的writer拟合过程，不是在线免校正LC1执行。即使84/84训练态全部通过，也不等于LC2闭合：完整writer仍需冻结，再按单独前瞻协议验证新状态及严格隔离的排除输入。本轮不准备新状态、不打开新确认或排除输入、不部署writer、不改父判定，`LC2_closed=false`。

交付前本地验证包括合成完整归档、注入的上游上下文，以及真实CPU小型共享权重神经网络上的AD、SciPy LP、8步更新、封存和异常恢复测试。小型网络测试不代表GPT-2复现；真实25个科学原包及真实C180模型实验未在交付前执行。详细记录见 `LOCAL_VALIDATION.json` 与 `delivery_validation/`。
