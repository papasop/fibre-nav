协议：`GPT2_LC2_C172_FINAL_HEAD_FINITE_STEPS_CPU_V1`。

## 使用

1. 在Colab CPU会话运行完整 `C172_CPU_LAUNCHER.py`。
2. 仅上传配套 `C172_CPU_LAUNCHER_BUNDLE.zip`，无需解压；启动器不内嵌科学源码。
3. 挂载原Drive。程序按固定路径与SHA256定位C155–C171共17个科学原包。不要上传科学结果代替BUNDLE。
4. 自测后执行真实GPT-2模型探测，工作进程上限180分钟，自测与依赖检查另计。成功或失败均封装一个结果总ZIP，并尝试校验备份到Drive。

不需要GPU；子进程使用CPU和2线程，不更改父会话GPU屏蔽设置。保留系统PyTorch与NumPy，将固定HF与SciPy依赖放在隔离目录。如果原科学ZIP已移动，可在启动器顶部填写对应的绝对路径，但原包字节哈希仍必须一致。内存开销与实际耗时需本轮实测，不预先保证。

## 预登记探测

- 在固定最终头上重放两轮原生端点，并与原C170固定最终端点对应轮次比较；第一轮原生重放先于梯度。FP64锚点观测/KL须满足原有2e-9重放容差，随后才允许求解LP，不重定参考基线。
- 全84态各测一次FP64响应损失和guard损失的系数梯度，共168次标量反传。活跃集使用响应训练损失>0，不能只保留五个原生失败态；训练安全裕度仍是0.0018，原生响应门槛仍是0.002。
- 最多一次响应梯度LP。为全部六臂预留空间，自由掩码固定为 `abs(p)<=0.125-0.001`；其他坐标方向为0。guard梯度记录但不作为LP约束。严格重算给定binary64梯度/方向的有理数点积；非空活跃集没有严格负点积则停止，不换求解器或回退方向。空活跃集使用零方向且不调用LP，不伪报严格下降。
- 三个固定正步长：1e-4、3e-4、1e-3；分别使用正负方向，共六臂。每个实际binary64头独立检查原系数盒，不裁剪头、不缩步长、不回溯。
- 一次梯度批次之后、任何探测观测之前，封存全部六个NumPy头及全部实际Torch FP64点。梯度测量明确早于这次封存，不声称六臂在所有模型测量前就已形成。
- 全六臂各测全部84态FP64端点；随后重复84态FP64锚点。原生FP32评价包括锚点和六臂各两轮，1176条门槛记录，失败不截断后续臂。

请求总量：1848条有序记录、3699次真实模型前向（其中1346次functional FP64）、168次标量反传、最多1次LP；672个实际FP64点、588个原生FP32点、588对原生重复。模型初始化的3次前向计入总量。零个训练更新、零个确认/排除输入状态、零个新Jacobian/SVD。

## 输出与证据边界

结果总包含全部有序记录、固定输入与源码、点封存、原LP向量、精确记录梯度证书、全部原生门槛、252条方向差分对比与504条正负损失变化，并分别报告响应、read/KL/radius和regularizer。方向差分与AD的偏差是描述量，不是导数误差上界或曲率证书。

比较的六臂共享本轮同一方向；该方向与C170之前方向的差异同时可能涉及头位置、梯度、自由掩码和LP返回值。跨实验比较不能单独归因于步长或硬件。guard总损失增加不能直接判为功能保持失败，硬门槛由原生端点单独判断。

不选择最优臂、不部署头、不更改父判定、不按本轮表现自动开启后续训练。任一臂即使84/84，也只构成训练诊断，不建立新确认、排除输入泛化或LC2通过。LP证书只认证记录的binary64代数关系，不认证真实导数、求解器最优/不可行性、全局可行性、曲率界、收敛、统计因果、真实时序或未访问行为。LP内部线性系统计数未知，保留null，不能填0。
