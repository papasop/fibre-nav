## 本轮唯一科学问题

C176 的8步已被 C177 的归档审计复核：当前84个训练态原生验收仍为79/84；逐步响应损失下降，最大原生响应漂移降至0.00222015380859375，尚高于固定门槛0.002。本轮检验 **同一全坐标训练法从固定 C176 最终头再走8步的结果**，不根据中间好坏选择头或步长。

初始共享系数头的张量摘要固定为：

`c4e6a00d16a11069c2f1d345092c76d80bec6b44a752e4c3fed89c4f3a8abdab`

开始模型计算前，独立重算原C176全部8步、840个已封存FP64点、16份记录内仿射证书、原生门槛和C177逐步诊断；绑定原C177的源码、摘要、祖先哈希及重建产物。初始原生两轮和首批FP64还须与原C176固定最终端点重放一致。任何不一致都保留错误，不重定基线、不改阈值。

## 冻结协议

- 原84态全部保留。历史名称中含 `confirmation` 的态已进入训练，不是新的确认态。
- 固定8个更新槽，每次系数更新 `p_next = p + 0.001 * direction`，binary64；不投影头、不搜索步长、不选最优中间头。
- 每步对所有84态重新求6个有符号响应坐标的系数梯度及响应/guard两项标量损失梯度。每步最多一次原固定设置的LP，保留全84×6×2＝1008条有符号约束。
- 每步线性化上限为该态 `max(0.0018, 当前六坐标最大绝对响应)`。**这是训练约束，不是新的原生验收门槛。** 原生响应门槛仍为0.002；原有KL、读出裕度、更新半径、模型/制备态/路由/V及原C155响应/logit参考不变。
- 方向和实际binary64新旧头差都须取得记录内正仿射裕度证书；空活跃集仅允许已登记的零更新且不调用LP。证书失败则停止并封装未完成结果，不回退或改选检查点。
- read/KL/radius/regularizer guard均测量和记录；**此响应LP不约束guard**。精确证书不保证有限步长端点、真实导数、曲率、求解最优性或收敛。
- 只对固定本地第8步头做全84态两轮原生完整验收，加最终FP64重复测量。从C176起累计16个离线更新槽；不代表16次在线免校正写入。

## 工作量与预算

完整科研工作请求：2355次模型前向（其中1682次functional FP64），5376次标量反传，672个系数响应Jacobian块/4032个响应坐标梯度行，最多8次LP；1176条记录、840个实际FP64点、336条原生端点记录。这里只构建共享系数头的响应Jacobian，不构建全模型参数Jacobian；没有SVD。

工作进程硬上限 **240分钟**，自测、依赖准备和打包另计。CPU速度不同，不能保证每个运行时都在预算内完成。若超时，已完成更新和部分记录仍进入唯一结果总包；部分结果不获得最终验收。

运行时保留系统CPU PyTorch/NumPy，在隔离目录检查或安装固定 transformers4.56.2、peft0.17.1、tokenizers0.22.0、huggingface_hub0.34.4、accelerate1.10.1、safetensors0.6.2、SciPy1.17.0。模型仅在同一工作进程加载一次。只对子进程屏蔽GPU，不修改笔记本内核GPU环境。
