# C182：从C180固定最终头继续八步全响应坐标训练（CPU）

## 使用

在 Colab CPU 运行时运行 `C182_CPU_LAUNCHER.py`。提示时一次上传 **C182_CPU_LAUNCHER_BUNDLE.zip**，无需解压，不需要另选SOURCE.zip。科学结果ZIP不能代替配套BUNDLE。

挂载原 Google Drive 后，程序按固定路径及SHA256读取C155–C181共27个原始科学结果包。若文件移动，在启动器 `INPUT_PATHS` 对应键填写本地绝对路径即可；内容仍须匹配原哈希。BUNDLE只包含固定源码，不包含27个科学结果包或GPT-2模型权重。

工作成功或失败均封装一个结果总包，含日志、摘要、逐态记录、实际封存点、更新证书和源码。尝试自动下载及Drive备份，备份后比较SHA256。源码包哈希不匹配会在执行实验代码前拒绝。

## 固定起点与问题

供应日志报告：C180完整执行八步，原生两轮均80/84，仍有四个响应失败态；最终原生最大响应0.0021820068359375，FP64最大响应0.0021728165356904583。C181只读审计保留该判定，重建八步全部坐标训练上限，并确认最终原生/FP64响应判定分歧消失。这些是父实验报告，不是C182预设的成功结果。

C182只从原C180预定第8步最终头继续，不从中间头、恢复头或探针选择起点。初始头摘要固定为：

`3a49ff32146b08b145442f226a63d743e1aa1d5bb997e18004f678ec7e606eca`

模型加载前，先重新绑定27个原包，使用不可变C181检查器独立重建原C180，并核对原C181源码、完整摘要、上游来源、全部重建算术和诊断产物，包括336条精度裕度JSON/CSV和168条精度转换记录。首批FP64及原生两轮起点观测必须满足原C180重放容差与点身份；不重置或重定心参考输出。

## 不变的训练日程

- 同一GPT-2修订、LoRA-A、已暴露的84个训练态、参考输出、V、路由及参数图；生产系数头形状3×2×36。
- 固定8步，每步0.001。每步在全部84态记录六个响应坐标梯度，以及响应损失和guard损失梯度；每步保留84×6×2＝1008条有符号LP约束，最多调用一次固定SciPy求解器。
- 每次提交前保存方向、下一头和实际binary64头差，核对两种精确归档仿射证书。空活动集使用登记的零方向且不调用LP；证书不成立或重放不一致即保留部分工作并停止，不搜索步长、不重试或改选头。
- 训练响应上限仍为 `max(0.0018, 当前六坐标最大绝对响应)`。它不是新的原生验收门槛。Read、KL、半径、正则guard及其梯度继续记录，响应LP不提供有限更新后的guard保持保证。
- 只验收预定本轮第8步最终头：全部84态两轮原生完整门槛，以及最终FP64重复。不选最优检查点，不因中间结果提前资格认证，不修改响应0.002、KL、读裕度、更新半径或其他门槛。
- C176/C178/C180/C182累计32个续训槽，从C170固定最终头之后计数，不包括C170自己的八槽。

历史ID含confirmation的状态在本轮均是已暴露训练态，不是新的确认态。本轮不准备新状态、不打开新确认或排除输入。

## 精度报告与主要输出

继续从已有初始/最终端点观测导出84态×2个头×2轮原生测量＝336条精度裕度记录，不增加模型前向。分别报告原生完整门槛、原生仅响应、FP64仅响应、距0.002的有符号裕度和响应判定分歧。

FP64仅响应通过不是新增验收门槛，也不建立FP64完整验收；两种精度一致不能作为准确度界或硬件误差原因。

## 成本与证据边界

CPU工作进程上限240分钟，自测、依赖安装和打包另计。完整科研工作计划2355次模型前向（含1682次functional FP64前向）、5376次标量反传、672个系数响应Jacobian块及4032行响应坐标梯度、最多8次LP，保存840个实际FP64点。原求解器内部线性系统次数未知，记录null。仅子进程屏蔽GPU，保留笔记本内核GPU环境。

本轮显式使用离线Jacobian和LP拟合writer，不是在线免校正LC1执行。即使训练态84/84全过，也不等于LC2闭合；完整proposal流程仍需冻结，再按独立前瞻协议验证新状态与严格隔离的排除输入。不部署writer，不改父判定，不外推还需多少步，`LC2_closed=false`。

交付前测试包括合成完整归档、明确注入的上游上下文，以及真实CPU小型共享权重神经网络上的AD、SciPy LP、固定更新、封存与异常恢复。小型网络测试不是GPT-2复现；真实27个科学原包及真实C182模型实验未在交付前执行。详见 `LOCAL_VALIDATION.json` 和 `delivery_validation/`。

源码包安全解压采用固定1500文件上限，以容纳新增的不可变父源码及测试记录；整体哈希、逐文件清单和32MiB解压大小上限继续检查。这仅是源码容器限制，不改变任何科学验收阈值。
