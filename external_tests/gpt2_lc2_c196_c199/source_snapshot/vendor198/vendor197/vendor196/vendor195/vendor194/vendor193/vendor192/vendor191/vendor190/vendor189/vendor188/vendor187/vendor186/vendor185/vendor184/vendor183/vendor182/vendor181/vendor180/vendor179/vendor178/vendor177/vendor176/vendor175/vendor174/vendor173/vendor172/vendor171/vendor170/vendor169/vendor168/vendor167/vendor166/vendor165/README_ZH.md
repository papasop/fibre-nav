# C165：共同响应下降方向与固定小步验证（CPU）

配套为 `C165_CPU_LAUNCHER.py` 和一个 `C165_CPU_LAUNCHER_BUNDLE.zip`。启动器不内嵌科学源码。把启动器粘贴到 Colab CPU；只在提示时上传一次配套 BUNDLE，无需解压。C155–C164 十个科学原包从已挂载 Drive 按固定路径和完整 SHA256 定位，也可以在启动器填写各原包的绝对路径，哈希要求不变。

## 本轮问题

C164 核对了 C163 全部8步及756个实际 FP64 点；原生门槛仍79/84，同样5个响应失败。C163平滑目标降低而原始最坏态目标升高。C165从 **C163固定最终第8步头** 出发，重新计算所需梯度，并实际验证一个预先规定算法生成的方向。没有重新选择旧头，也不把这84个已暴露状态当新确认或留出输入。

## 固定流程

1. 只读绑定全部十个原包，独立重算 C163 与 C164，核对固定最终头。新模型测量之前先固定1848条请求和全部规则。
2. 加载一次原固定 GPT-2；基础模型和 LoRA-A 不变。先对84态重放原生 FP32 端点，再对全84态重新计算原响应损失 R 与合计保护损失 G 的完整系数梯度，共168次标量反传。与 C163 原端点的重放不一致时，在计算方向之前停止，保留失败记录并封装。
3. 收集 **所有 R>0 的状态**，而非只挑5个失败态。R沿用原训练安全响应尺度0.0018；实际验收门槛仍0.002。对响应梯度进行投影及逐行L2归一化，用固定4096次 Frank–Wolfe 代数迭代近似求最小范数凸组合，取负组合并归一化到单位Linf方向。每次迭代记录保留。该阶段不调用模型，也不调整后续探测步长。
4. 为保证正负对称步长都满足原系数盒，固定排除离±0.125边界不足最大步长的坐标。此限制可能排除有用的单侧方向；未找到方向不能证明整体不可行。正损失而投影梯度为零的状态仍保留为零行。组合范数≤1e-12或无正响应损失时使用显式零方向，仍完成全部预登记探测。
5. 固定3个系数步长：`1e-6、5e-6、1e-5`，每个都测正负，共6个临时探测头。全部头、全84态原生FP32提案和实际Torch FP64点在第一次新头探测前封存；不裁剪探测头、不搜索或挑选步长。
6. 每个探测头计算全84态 FP64 观测，作3组中心差分，并重测全84态 FP64 锚点。每个探测头与原锚点均作两轮完整84态原生 FP32 验收，原内容、响应、KL、读出与半径门槛不变，保存失败、救回及破坏态。

## 计算与封装

- 固定3699次模型前向（其中1346次功能式FP64前向）、168次标量反传、1848条端点/梯度记录。
- 保存672个实际Torch FP64坐标数组，在模型前向前检查实际图点哈希；保存所有临时头和原生提案。全部十个输入原包保持只读。
- 没有模型参数训练或新写入器头拟合；**有明确记录的离线方向优化**，最多4096次代数迭代。没有新Jacobian/SVD或线性方程求解。
- 正式工作进程上限180分钟，自测另计。使用CPU；隔离安装原固定HF依赖并保留系统Torch/NumPy，不要求GPU。子进程屏蔽GPU，不修改父内核GPU设置。
- 成功或执行失败均生成一个结果总包，含日志、报告、逐态/逐臂明细、点与头封存、方向迭代和源码；Drive可用时备份。

## 结论边界

方向算法只针对 R>0 的响应损失，不给其他门槛或R=0状态提供一阶保护保证；因此全部84态实际门槛必须另测。有限迭代的浮点公共下降判据不是严格可行性证书；未找到方向也不是不可行性证明。中心差分与AD分歧可能包含非光滑或有限步因素，不能单独归因为AD错误或曲率。

方向使用了本轮训练态写后观测及梯度，6个头仅为诊断，不构成免校正写入器。本轮不选择任何头或步长、不部署、不访问新确认/排除类状态，不改写C163/C164判定，不计LC2通过。即使某个探测头84/84通过，也只算本轮已暴露训练态诊断结果。

本地验证包含真实小型CPU Torch模型的完整1848记录路径、AD与同函数差分、实际坐标哈希、异常恢复、重放失败拦截、上传入口和十个合成原包的完整串联。它们不能替代真实GPT-2科学原包的正式运行。
