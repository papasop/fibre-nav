# C183：C182固定八步续训的CPU只读归档审计

## 使用

在 Colab CPU 运行时运行 `C183_CPU_LAUNCHER.py`。提示时一次上传 **C183_CPU_LAUNCHER_BUNDLE.zip**，无需解压，也不需要另选SOURCE.zip。不要上传科学结果ZIP代替源码包。

挂载原 Google Drive 后，程序按固定路径和SHA256读取C155–C182共28个原始科学结果包。文件移动时可在启动器 `INPUT_PATHS` 对应键填写本地绝对路径，内容仍须匹配原哈希。配套BUNDLE只有固定源码，不包含28个科学结果包或模型权重。

工作成功或失败均封装一个结果总包，包含日志、报告、逐态明细、重建算术和源码；尝试自动下载、Drive备份并比较备份SHA256。源码包不匹配会在执行审计之前拒绝。

## 新增活动集核对

从已经核验的九帧响应损失重建全部84态的活动标志，并逐步核对归档LP活动注册表。完整导出84×8＝672条活动转换与84条状态轨迹：

- 哪些态在哪一步退出、进入或再进入活动集；不只比较起点和终点数量。
- 实际FP64响应何时跨入或跨出0.0018训练安全范围，以及0.002原响应预算。
- 活动状态变化态的全部九帧响应、损失、出入步骤和原生两轮完整端点门槛。
- 保留活动集再扩大、状态再进入、响应反弹、两端数量相同而中间发生出入等情况，不预设6→5。

活动退出不等于新增原生获救。0.0018安全尺度与0.002响应门槛不同；中间FP64帧也不是中间头的完整原生验收。历史ID含confirmation的84态均已暴露并用于训练，不是新的确认态。
