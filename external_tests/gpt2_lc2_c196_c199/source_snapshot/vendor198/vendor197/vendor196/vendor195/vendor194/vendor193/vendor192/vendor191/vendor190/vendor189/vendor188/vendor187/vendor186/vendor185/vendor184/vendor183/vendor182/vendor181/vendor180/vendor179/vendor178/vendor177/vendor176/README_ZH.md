## 使用

在 Colab CPU 运行 `C176_CPU_LAUNCHER.py` 的完整内容，只上传一次匹配的 `C176_CPU_LAUNCHER_BUNDLE.zip`，无需解压。启动器不内嵌科学源码。C155–C175共21个原科学结果由程序从原Drive路径按固定SHA256定位，不要将结果ZIP当作配套源码ZIP。也可填写各 `Cxxx_ZIP` 的绝对路径，但内容仍须匹配固定哈希。

系统CPU PyTorch和NumPy保留，HF/SciPy依赖安装至独立目录并核对固定版本。工作进程最多240分钟，自测和依赖准备另计，CPU时限不是运行时间承诺。不改变Notebook进程的GPU可见性。成功或研究进程失败均封装一个结果总ZIP，包含摘要、报告、日志、逐态记录、每步梯度/LP/精确证书、固定最终头与源码；尝试以相同SHA256备份Drive并下载。

## 固定训练协议

1. 原生初始84态第0轮重放，核对原C174同点身份与门槛。
2. 固定8个更新槽，每槽固定步长0.001。每步在当前头重算全84态，每态六个有符号响应坐标梯度、响应损失梯度和guard损失梯度，共672次标量反传。
3. 每步最多一次1008行线性规划：全部84×6×2响应约束均保留，包括当前零标量损失态和非最大响应坐标，不做行L2归一化。训练上限是 `max(0.0018,当前态最大响应)`。
4. 对0.001×方向和实际binary64头端点精确差分别计算有理数仿射证书。活跃集非空时，两份证书的全部1008条最小归档松弛必须严格为正后才提交。空活跃集使用零方向/不调用LP，仍保留8个预登记槽。
5. 证书无法通过或完整性检查失败即停止为未完成，保留部分计数与记录；不重试求解、不缩步、不回溯、不选中间头。guard损失及梯度记录但不作为LP约束，实际最终原生门槛决定训练资格。
6. 冻结预定第8步头，运行全84态FP64端点及重复、最终原生第0轮、初始原生第1轮、最终原生第1轮。所有失败保留，回滚/重试不更改分母。

## 完整路径计数

- 1176条有序记录；2355次模型前向（1682次functional FP64）；5376次标量反传。

- 最多8次LP，每次1008条有符号约束。原求解器内部线性求解数未知，保留null。
- 840个实际FP64点、168个原生FP32点；336条原生验收记录、168个原生重复对和84个最终FP64重复对。
- 只评估固定最终头；中间头及探测头不参与选择或部署。

## 判定边界

训练线性化上限不是原生0.002响应预算。精确证书只证明归档binary64响应/Jacobian的仿射算术，不证明真实导数准确、有限误差界、guard保持、收敛、全局可行性或泛化。C176显式使用离线Jacobian和LP，此训练过程不构成在线免校正LC1执行。

即使两轮84/84训练通过，也仅获得训练资格，不自动开启确认、不评估排除输入、不闭合LC2。保持原验收阈值和既有实验判定。
