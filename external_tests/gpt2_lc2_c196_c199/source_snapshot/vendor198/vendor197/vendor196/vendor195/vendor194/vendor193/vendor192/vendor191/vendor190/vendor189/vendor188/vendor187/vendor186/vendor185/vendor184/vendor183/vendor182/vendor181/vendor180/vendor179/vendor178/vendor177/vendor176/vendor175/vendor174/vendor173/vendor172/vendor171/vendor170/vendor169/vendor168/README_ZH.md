# C168：C167精确方向的有限写入探测（CPU）

C167已在归档binary64梯度定义的线性问题上证明9条活跃响应梯度存在共同下降方向。C168要检查这个**固定方向**在真实GPT-2的有限步长和原生FP32提交中是否带来改善。它仍是全部84个已暴露训练态的诊断，不是新确认态或排除输入评估。

## 使用

1. 在Colab选择CPU，把 `C168_CPU_LAUNCHER.py` 粘贴到单元格运行。
2. 提示时仅上传 `C168_CPU_LAUNCHER_BUNDLE.zip`，无需解压；启动器不内嵌科学源码。
3. 挂载Drive。C155–C167十三个固定科学结果ZIP按已知路径与SHA256定位；若移动，可填写各 `Cxxx_ZIP` 的绝对路径，哈希不变。
4. 输出一个结果总包，含完整源码、日志、独立归档核对、固定方向、六个临时头、实际参数点、逐态门槛和诊断。失败也封装并尝试Drive备份。

工作进程硬上限180分钟，自测和依赖检查另计。需要CPU版或可在CPU使用的PyTorch；在隔离目录补齐原固定HF版本，不替换现有PyTorch/NumPy。首次模型加载可能需要从HF下载原固定revision的GPT-2。本启动器不提交GPU任务或付费HF任务。

## 固定输入与精确证书

交付时固定C167结果SHA256：`6e886320ff90063f44220bd4e6f5be9aeebf39b6779abb02c507ad7014b64401`。

先独立重建C163–C166相关原始算术，重新打开C167原包，将全部84条梯度、完整线性问题、原C163最终头、坐标掩码和证书数组与原C165绑定。用Fraction重算原证书，只有严格正的共同裕度下界才能进入模型阶段。C168不重新求LP、不改变方向、不构造新Jacobian/SVD，不执行归档源码。

## 写前步长规则

设原固定头为p，C167方向为d，系数盒为[-0.125,0.125]。

- 用精确有理数计算双向边界距离 `r=min_{d_j!=0}(0.125-|p_j|)/|d_j|`。
- `h3=min(0.001,r/2)`，向下转换到binary64；`h1=h3/100`，`h2=h3/10`。
- 六臂为 `p±h1*d`、`p±h2*d`、`p±h3*d`，逐一检查真实binary64头在原盒内，不裁剪、不重试、不搜索。

这使最大探测步长可比C165的1e-5更大，同时保留至少一半双向边界裕量。它仅由写前系数和已冻结方向决定，任何新测量都不参与步长计算。

所有NumPy头、完整84态参数映射和原生FP32点在模型初始化前封存；八批实际Torch FP64参数点（锚点、六臂、锚点重复）在第一次状态测量前封存。每次FP64前向校验实际点字节；原生提交也校验实际FP32坐标，结束恢复零LoRA-B，保持基础模型和LoRA-A。

## 固定工作量与顺序

- 原生锚点84态第一轮；FP64锚点84态。
- 六臂各84态FP64；FP64锚点84态重复。
- 六臂各84态原生第一轮；原生锚点第二轮；六臂各84态原生第二轮。

总计1848条记录、3699次模型前向（含3次初始化/基线前向），其中1346次功能性FP64前向；0反传、0训练、0新求解。保存672个实际FP64点、588个原生FP32点，对1176条原生端点作原门槛验收，保留588组原生重复比较。

初始锚点必须重放原C165同一头的FP64及原生观测；漂移或身份错误会在新探测前阻断并保留失败记录。新探测臂的门槛失败不会触发筛态、早停或更换步长；已登记六臂全部测量。

## 报告与解释

每个臂分别报告全部84态的内容、响应、KL、读取裕度等原始完整门槛；响应0.002等预算不变。报告相对锚点的救回/破坏、FP64响应、三组中心差分以及504条单侧响应/保护损失变化。差分对照使用C165归档AD在相同精确头上的点积，明确不冒充本轮重新计算的AD。

不选最优步长、头或部署方案，不把FP64响应单项通过当成完整验收，也不把任何训练态改善当成LC2闭合。真实的有限写入效果由本轮实际测量决定；几何可行方向并不保证保护项、有限步长或排除输入泛化。C165–C167历史判定保留。
