# C166：C165 方向与固定探测的纯 CPU 只读审计

配套为 `C166_CPU_LAUNCHER.py` 与一个 `C166_CPU_LAUNCHER_BUNDLE.zip`。启动器不内嵌科学源码。把启动器粘贴到 Colab CPU；提示时仅上传一次配套 BUNDLE，无需解压。C155–C165 十一个原始结果 ZIP 从已挂载 Drive 按固定路径和完整 SHA256 定位，也可以填写各原包绝对路径，哈希要求不变。

C165完整测完6个固定正负小步头，两轮原生验收均79/84，未满足原严格共同响应下降判据。C166只复核归档与方向数值，不追加模型运行，不选头、步长或其他迭代结果。

## 核对范围

- 固定十一个原包的完整哈希、成员清单、交付源码和父链。新审计之前独立重算 C163/C164。
- C165全部1848条有序请求与记录：84对响应/保护梯度、504个FP64探测端点、84个FP64锚点重复，以及1176个原生端点。
- 核对固定C163最终锚点、6个临时头、672个实际FP64坐标数组、588个保存的原生FP32提案及全部封存/行绑定，重算实际点与独立NumPy映射的差异。
- 重建全部R>0状态注册表、双侧内部坐标掩码和归一化投影梯度矩阵；逐步核对原4096次迭代的规范最小顶点、标量二次线步、FW间隙和组合范数。若原协议没有正损失状态，原迭代数为0，仍核对全部零方向探测。
- 独立重建最终凸权重、组合向量、保存的方向、全84态响应/保护梯度点积及原严格下降判据；导出未满足原判据的状态和末256次迭代趋势。只重放原记录，不重新优化方向。
- 独立重算3组固定步长、全84态的252行响应/保护标量AD与中心差分，以及1512行响应坐标中心差分（未测坐标AD）；不增加“AD一致性通过”阈值。
- 重算全84态、全部7个头（锚点加6臂）、两轮共1176个原生端点的内容、响应、KL、读出和半径门槛，588对原生重复及84对FP64重复。失败、救回、破坏态全部保留；各臂并列报告。
- 导出JSON/CSV明细、最终组合范数、FW间隙、末段趋势、逐步标量核对误差、3个步长的AD/FD差异，以及1176条FP64与原生响应比较。

## 边界

仅依赖NumPy，不导入Torch/HF或加载模型；无前向、反传、训练、头拟合、新方向优化、线性方程求解或新Jacobian/SVD。归档源码不执行；审计使用交付的固定读取器。

原梯度是归档输入，KL也是归档标量；未独立重新测量它们。浮点组合范数、FW间隙、点积符号和中心差分不是最优性、收敛、可行性、不可行性、AD错误或因果解释的证书。双侧坐标子空间本身有限制。字节与封存接收单的一致性也不能证明真实时间先后、未访问留出信息或模型确实消费了保存点。所有原判定保留，LC2仍开放。

工作进程上限30分钟，自测另计。仅需系统NumPy。CPU子进程屏蔽GPU，不修改父内核GPU设置。成功或工作失败均封装一个结果总包，含日志、中文报告、逐态/逐臂/逐迭代明细、审计源码和清单；Drive可用时备份。

本地测试包含完整1848记录合成归档、4096次原迭代重放、近反向/零梯度控制、重新绑定后篡改拦截、启动与失败封装、完整十一个合成原包串联，以及真实BUNDLE上传入口。本地测试不替代用户真实科学原包的正式审计。
