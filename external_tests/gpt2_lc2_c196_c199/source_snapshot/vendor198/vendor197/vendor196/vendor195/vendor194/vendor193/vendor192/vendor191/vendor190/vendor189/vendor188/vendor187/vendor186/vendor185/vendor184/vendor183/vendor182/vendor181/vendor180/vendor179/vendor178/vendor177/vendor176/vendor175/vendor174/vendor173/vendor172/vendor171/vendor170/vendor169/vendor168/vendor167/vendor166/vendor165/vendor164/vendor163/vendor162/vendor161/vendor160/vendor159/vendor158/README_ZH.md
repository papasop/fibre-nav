# C158：同次运行 FP64 AD／方向差分（CPU）

C157 R2 在一次原生 FP32 初始化后因跨运行基线重放不一致停止，未进入方向反传。C158 是单独登记的新诊断协议，C157 保持 incomplete，LC2 仍开放。

## 使用

将独立的 `C158_CPU_LAUNCHER.py` 全文放进 Colab CPU 单元运行，提示时仅上传配套 `C158_CPU_LAUNCHER_BUNDLE.zip`，不需解压。启动器不内嵌科学源码。C155、C156 和确切失败的 C157 R2 科学结果从原 Drive 位置按固定整包哈希定位；也可填写对应绝对路径。BUNDLE 与科学结果不能互换。程序最终只输出一个结果 ZIP（成功或失败均打包），包含原始差异、诊断、冻结点、源码和日志，并尝试备份到 Drive。

## 固定问题

在一个新建但身份固定的 CPU 模型运行中，对两个已经暴露的训练态检验：在完全相同的 FP64 物理直线路径上，标量 alpha 的自动微分和预登记三个尺度的正向、负向、中心差分分别是什么？本实验报告差异，不设导数正确性通过阈值，不选最佳步长或头。

两态固定为：

- `xor_11__c141_confirmation_p09_n01_d00`
- `xor_11__c141_confirmation_p08_n01_d00`

路径是 C155 的零点与 +1 物理端点的精确 FP64 转换所定义的直线；可微路径内无 FP32 转换。它不等于旧系数映射的所有中间点；所有这种差异会保留。

三个固定参考：本次 FP64 **全零 LoRA-B 图基线**、归档 C155 FP64 参考、归档 C155 FP32 缓存参考。第一个参考不是非零 chord alpha=0 写入端点。首次零图 FP64 前向后重复一次，并在焦点态探测之前封存三种参考。响应损失分别为 `relu(max(abs(response-reference))/.0018-1)^2`；不包含 KL、读取或完整84态目标。

跨运行 FP32/FP64 基线及四个原端点的差异全部报告，并显示历史 2e-9 比较结果；它们不作为这个新同次运行诊断的通过门。这一协议变化不改写 C157、不重新评分历史 writer，也不修改 LC2 接受门槛。原包/源码/实际张量绑定、模型身份、有限值以及冻结物理/FP64参数检查仍必须通过。本次 FP64 零基线重复、AD/无梯度中心、端点预检和末尾零/+1重复仍须符合 2e-9 运行内一致性检查。

## 固定分母与预算

1 原生 FP32 初始化 + 2 FP64 零图基线 + 4 端点预检 + 2 AD 前向 + 14 差分前向 + 4 重复 = **27 次模型前向**，其中26次FP64。每态6个响应坐标和3个参考损失分别对同一标量 alpha 求导，共 **18 次标量反传**；不是参数 Jacobian。封存14个点、2个方向、24个状态级请求。每态保留 h=0.25、0.5、1 的全部结果。

工作进程上限120分钟，自测和依赖检查另计。系统 PyTorch/NumPy 保留，六个 HF 包使用独立目录的固定版本。CPU子进程不改变父内核的GPU环境变量。第一次使用可能下载固定 GPT-2 模型。
