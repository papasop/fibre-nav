# C138 V2：原writer扩展字段的读取修复

V1在六原包绑定后、模型初始化之前，因 `Frozen raw writer schema` 停止。提供的日志记录模型前向0次、新态评估0态、端点0条。这是读取器兼容性错误；C137训练资格与C138的科学判定均不因此重分类。

根因是V1将raw预测实际使用的五个字段误当成原writer的完整键集合。已有归档生成源码 `worker_lc2.py` 在共享预测头上继续保存 `J_mean`、`B_all`、`B_response` 和 `response_offset`。预测函数仅使用五个核心字段；旧组合写入机制使用另外四项几何字段。

V2要求五个核心字段存在，并对原有四项几何扩展逐项核对有限浮点类型及形状：J_mean=(22,36864)，B_all=(36864,22)，B_response=(36864,6)，response_offset=(6,)。未知字段、缺失核心字段、非有限数值、错误形状与非法归一化仍阻断。所有原字段完整保留并纳入冻结哈希；不裁掉字段，不重新拟合，不把几何扩展接入本次raw或C137提案计算。

协议版本改为CPU_V2，仅标记读取器修复。原六ZIP哈希、C137第24步候选、V、writer数值、归一化、24态注册表、随机种子、扰动幅度、96端点分母和全部科学门槛保持不变。V1未进入新态测量，因此V2使用同一注册表，未因测量结果重选状态。

新增测试使用与原生成源码一致的九字段结构，检查扩展字段保留、形状、非有限拦截及扩展值不影响raw/共享控制提案，并在完整24态/96端点解析流程中保存及核对全部九个字段。交付前仍未读取用户六个实际科学ZIP或运行真实GPT-2；这些由Colab原包绑定和已知点重放完成。

启动器与BUNDLE均使用V2文件名，避免与V1混淆。V1失败结果保留，不覆盖。
