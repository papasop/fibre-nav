# C164：C163 平滑风险训练的纯 CPU 只读审计

配套为 `C164_CPU_LAUNCHER.py` 与单个 `C164_CPU_LAUNCHER_BUNDLE.zip`。把启动器粘贴到 Colab CPU 单元执行；仅在提示时上传一次 BUNDLE，无需解压。启动器不包含科学源码。C155–C163 九个原始结果 ZIP 按已固定路径和完整 SHA256 从挂载的 Drive 读取；可在启动器填写各原包的绝对路径，哈希要求不变。

本轮不是继续训练，也不选择候选头。独立核对 C163 从 C161 固定第8步头开始、Adam 动量清零、固定温度0.01和8步更新的完整记录。

## 固定核对范围

- 九个原始 ZIP 的完整哈希、成员清单和交付源码绑定；独立重算 C161/C162 父链。
- 全部672条训练观测、84条最终 FP64 观测、8步梯度聚合和 Adam 更新；固定最终头必须等于更新8，不能选择中间头。
- 保存的756个实际 Torch FP64 点：数组字节、点哈希、头身份、9批接收单、行绑定及其与独立 NumPy 映射的原1e-12容差比较。168个保存的原生 FP32 提案也重建并重哈希。
- 全部336条原生端点和168对重复测量，原内容、响应、KL、读出和半径门槛不变；失败、救回、破坏态全部保留。
- 平滑目标、原始 hardmax 目标、平均响应损失及最坏响应损失分别重算。
- 全84态在9个头位置的756条响应裕度，全部672条记录梯度与实际更新的点积和观测变化，全84态梯度余弦；已暴露的固定5个失败态另外列出，不作为新评估子集。

## 边界

不导入 Torch/HF，不加载模型，不做前向、反传、训练、拟合、方程求解或新 Jacobian/SVD。不执行科学归档内源码。归档梯度仍是记录输入，KL仍是归档标量；不能证明真实导数、模型测量准确性、真实封存顺序、模型确实消费了保存点或未访问留出信息。点积、余弦和观测减线性预测仅供诊断，不证明优化失败原因、曲率界、收敛、不可行性或泛化。C163 的原判定保留，LC2 始终开放。

工作进程上限30分钟，自测另计。仅需已有 NumPy。CPU 子进程屏蔽 GPU，不修改父内核 GPU 设置。成功或工作失败均封装一个结果总包，内含日志、报告、逐态诊断、审计源码和结果清单；Drive可用时备份。无需上传原科学结果 ZIP。
