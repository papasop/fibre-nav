## 使用

在 Colab CPU 运行 `C177_CPU_LAUNCHER.py` 的完整内容，只上传一次与其匹配的 `C177_CPU_LAUNCHER_BUNDLE.zip`，无需解压。启动器不内嵌科学源码。后续程序从原Drive路径按固定SHA256定位C155–C176共22个科学原结果。不要上传科学结果ZIP代替配套BUNDLE。可选填写各 `Cxxx_ZIP` 的绝对路径，内容仍须匹配固定哈希。

仅依赖系统NumPy，不加载模型、Torch、HF或SciPy，不安装模型依赖。CPU审计工作进程最多60分钟，自测另计；实际用时取决于原包与Drive读取速度。不改变Notebook进程的GPU可见性。成功或研究进程失败均封装一个结果总ZIP，含报告、摘要、逐步/逐态/逐坐标明细、日志和源码；尝试以相同SHA256备份Drive并下载。

## 审计范围

1. 全部84态、8步、1176条有序记录及完整失败分母；核对原始请求顺序。
2. 从归档梯度独立重建每步84×6×2共1008条LP约束。使用C175独立算术实现，而非C176调用的C174生产问题/证书实现。总8064条约束、672个归档系数响应Jacobian块和4032行响应坐标梯度均保留。
3. 重算每步原始primal向量到固定方向的限幅与自由坐标映射；不运行LP。原求解器内部线性求解数保留null，本次新求解次数为0。
4. 分别核对8份方向证书和8份实际binary64头端点差值证书，共16份、16128条有符号精确算术记录；核对每步更新、提出/提交头一致性和封存文件。
5. 重建840个实际FP64点、168个原生FP32点、336条原生验收记录、168个原生重复对和84个最终FP64重复对。原验收门槛和参考输出不变。
6. 重算全部9帧/8步的响应损失、最坏响应、活跃集、坐标变化、实际与归档线性预测差异，报告所有逐步损失增加；保存4032条响应坐标仿射预测与实际观测记录。
7. 分别报告read、KL、radius和regularizer的逐帧均值、最大值和非零态数量，包含最终重复的检查；不预设guard增长仅来自正则项。保留初始失败态的完整轨迹，并核对原生/FP64响应门槛差异。

## 判定边界

C177完整执行表示归档审计完成，不代表C176训练资格通过。保留C176父判定，全部失败、初始/最终两轮结果和固定最终头均报告。

`max(0.0018, 当前态最大响应)` 是训练线性化上限，不替代原生0.002响应验收预算。正的记录仿射松弛不保证实际模型端点满足训练上限；逐坐标诊断会分别报告两者。有理数证书只证明归档binary64响应、Jacobian和头差值的算术，不认证真实导数、模型测量、KL真值、有限误差界、收敛、因果、时序、非访问或保存点实际被模型消费。

没有新模型前向、反传、训练、拟合、LP、方程求解、Jacobian或SVD；不准备新状态、不评估确认/排除输入、不选择或部署头、不改变阈值、不改写父判定，不计LC2通过。不得按这8步的局部趋势外推闭合所需步数或时间。
