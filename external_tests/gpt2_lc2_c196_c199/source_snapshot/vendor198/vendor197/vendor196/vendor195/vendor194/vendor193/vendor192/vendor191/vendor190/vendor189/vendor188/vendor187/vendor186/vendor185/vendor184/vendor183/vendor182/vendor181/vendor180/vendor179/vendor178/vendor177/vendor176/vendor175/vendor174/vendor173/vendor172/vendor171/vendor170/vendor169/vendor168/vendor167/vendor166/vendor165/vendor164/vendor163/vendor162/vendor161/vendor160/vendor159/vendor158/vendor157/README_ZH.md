# C157：固定两态 FP64 同函数 AD／方向差分

CPU 版本。将 `C157_CPU_LAUNCHER.py` 全文粘贴到 Colab，提示时上传一份 `C157_CPU_LAUNCHER_BUNDLE.zip`，无需解压。科学源码在 BUNDLE 内，启动器不内嵌源码。C155、C156 原科学结果按固定路径和 SHA256 定位；不是上传时选择的 BUNDLE。

## 此轮回答的问题

C156 的两个固定训练态显示 FP64 采样斜率的步长分歧更小，但没有重新计算 FP64 AD。本轮比较**同一 FP64 函数、同一零点、同一方向**的 AD 与全部三个固定尺度的中心／正向／反向差分。只诊断六个响应坐标与响应损失，不训练或选头。

原 C155 每个系数更新经过 FP32 物理提交，七个采样点不是一条可直接求导的连续路径。本轮明确注册新路径：

`theta(alpha) = float64(C155_zero) + alpha * (float64(C155_plus_one) - float64(C155_zero))`

零点和 +1 与原物理端点的精确 FP64 转换相同。其余点与 C155 原点的全部坐标差异在模型加载前记录。路径内不做 FP32 转换，也不把该路径的结果冒充原系数路径的梯度认证。尺度固定为 0.25、0.5、1.0，包含正负方向；不选择最佳步长。

## 固定工作量与过程

- 两个已暴露训练态：`xor_11__c141_confirmation_p09_n01_d00`、`xor_11__c141_confirmation_p08_n01_d00`。
- 原始 C155/C156 ZIP 重新哈希，复核全部1530条归档记录、588个物理点及 C156 保存的诊断；十个更早原 ZIP 不重新打开。
- 全14个 FP64 路径点、两个方向和请求顺序在模型加载前封存。
- 加载原固定 GPT-2 CPU FP32 模型；冻结参数与缓冲临时转换 FP64。物理模型仍为原 FP32 零坐标，不提交提议。
- 先重放原 FP32／FP64 零基线和两态的原零点／+1，异常即停止；不通过调整基线或容差补救。
- 仅标量 alpha 开启梯度，每态六个响应坐标、两种基线下的响应损失分别求导，共16次标量反传。
- 总26次模型前向：原生初始化1、FP64基线1、端点重放4、AD前向2、七点及重复18。无优化器更新，无参数 Jacobian／SVD／方程求解。
- 保留 FP64 自身响应基线与原 FP32 缓存响应基线；响应损失为 `relu(max(abs(response))/.0018-1)^2`。
- 工作进程上限120分钟，自测和依赖检查另计；只输出一个含源码、日志、完整记录和报告的结果 ZIP，并尝试备份 Drive。

输入 C156 优先查找其固定 Drive 路径，也检查上一轮日志中的 `/content/...` 本地路径。若它尚未备份且运行时已重置，先把**原 C156 结果 ZIP**保存回 Drive 或填写启动器的 `C156_ZIP`；不要改 SHA256 或以其他结果代替。

## 判定边界

`complete=true` 仅表示所有固定检查和测量完成。没有 AD/FD 一致性验收阈值，不认证 AD 正确／错误或 FP64 真值。全部差异、极值坐标、符号、采样点铰链状态和重复变化均保留。采样点无切换不证明点间光滑性。

本轮没有全84态 FP64 目标、KL／读出完整资格、新态制备、拟合、部署、确认或排除输入评估。两态诊断不能替代84态训练资格，更不能关闭 LC2。原 FP32 接受门槛与父实验判定保持不变。
