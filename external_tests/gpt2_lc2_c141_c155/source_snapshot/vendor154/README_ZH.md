# C154：真实 GPT-2 固定更新方向诊断（CPU）

## 使用

1. 将 `C154_CPU_LAUNCHER.py` 全文粘贴到 Colab 单元格运行。
2. 提示时只上传一份 `C154_CPU_LAUNCHER_BUNDLE.zip`，无需解压。启动器不内嵌科学源码，不要选择旧 BUNDLE 或科学结果 ZIP。
3. 挂载保存原结果的 Drive。程序按固定路径和 SHA256 自动定位 **C153、C152、C150、C149、C148、C147、C146、C145、C143 九个原包**，无需逐包上传。也可填写启动器顶部九个 `Cxxx_ZIP` 绝对路径；内容仍须匹配已固定哈希。无需 C151 结果包。
4. 使用 CPU。保留系统 PyTorch 和 NumPy，将固定 HF 依赖安装在独立目录；加载 GPT-2 前强制执行协议检查、实际启动入口检查和4项真实 Torch 前向烟测。无需 GPU，不启动付费云任务。
5. 科学工作进程上限 **120分钟**；协议自测40分钟、Torch烟测10分钟、依赖安装独立计时，每30秒有心跳。模型缓存缺失时会下载固定版本的公开 GPT-2。
6. 成功或运行中断均封装**一个结果总包**，包含日志、报告、源码、全部注册测点、逐次测量与诊断，并尝试备份至 Drive。不会部署任何探针或控制头。

## 为什么做本轮

C153 只读审计核对了 C152 的归档算术和门槛；它没有独立验证真实导数。C152 两条续训臂均为79/84，冻结C150为80/84。C154通过新原生前向观测，检查归档实际更新方向的有限变化表现，不继续训练或尝试新的学习率。

## 两个固定位置与固定方向

仅使用小步长臂 `cyclic_rate_1e4`，固定选择其 **step01 和 step12 更新前**的位置：

- `P0` 为该步归档 `UPDATE.npz` 的 `before`。
- `P1` 为同一步的 `after`。
- 方向 `D=P1-P0`；不归一化，不求新梯度，也不替换为某个最优方向。
- 固定测量 `P0+alpha*D`，`alpha={0,-1/4,+1/4,-1/2,+1/2,-1,+1}`。alpha=0和+1分别直接保留before和after原字节，其余采用声明的float64插值。
- 任何注册点越过原系数盒 `[-.125,.125]`，或任一方向为零，均在模型加载前停止；不裁剪、不缩步长、不选替代位置。

两位置的选择是依据已暴露训练诊断作出的新研究选择，不是对小步长的优越性证明。所有84态均保留为已暴露训练数据；历史状态名含 `confirmation` 也不构成本轮新确认。

## 计算与输出

每个面板保留全部84态，重算原C152全批量目标：

`J = .9*max(R_i) + .1*mean(R_i) + mean(G_i)`

其中响应安全值 .0018、读裕度安全值 .075、KL安全值 .0045、半径20和原正则保持不变。不能只取五个失败态计算全批量目标。

对每个固定h=1/4、1/2、1，报告中心差分、正/负单边斜率、归档聚合梯度与实际更新D的内积，并分开报告响应目标与guard均值。斜率单位是“每单位归档更新倍数alpha”，不是单位范数方向导数。

主要文件：

- `REPORT_ZH.md`、`SUMMARY.json`：中文报告及完整计数、判定。
- `FIXED_DIRECTION_DIAGNOSTICS.json`：两位置三步长差分、实际目标变化、归档方向预测及复测变化。
- `STENCIL_FROZEN_BEFORE_MODEL.json`、`ALL1512_REQUESTS_FROZEN.json`、`ALL1176_STENCIL_POINT_BINDINGS.json`：测量前封存、全部请求、参数与点身份，以及float32变化量。

## 结论边界
