# C151：C150 只读耦合与响应保持审计（CPU）

## 运行

将 `C151_CPU_LAUNCHER.py` 全文粘贴到 Colab 单元格。提示时只上传一份 `C151_CPU_LAUNCHER_BUNDLE.zip`，不要选择科学结果包，无需解压。

挂载原 Drive 后，程序按固定路径及 SHA256 定位 C150、C149、C148、C147、C146、C145、C143 七个原结果包；也可填写启动器中的七个 `Cxxx_ZIP` 绝对路径。只读原文件，不覆盖旧实验。

科学工作进程仅需 NumPy，上限 20 分钟；合成/篡改自测上限 40 分钟另计。没有 GPU、Torch 或 Hugging Face 依赖，不加载 GPT-2。调用方内核的 GPU 掩码不改变，仅子进程禁用 GPU。成功或失败均封装一个结果总包，包含审计源码、报告、完整日志和逐态诊断，并尝试备份至 Drive。

## 诊断报告

`RESCUE_AND_WORST_RESPONSE_COMPARISON.json` 分别报告通过态数、最坏响应漂移、最坏态 ID、训练安全值内态数及配对获救/破坏。

`ALL84_FINAL_RESPONSE_AND_BLOCK_DIAGNOSTICS.json` 保留各臂全部 84 态的六坐标有符号响应及裕度；报告耦合臂对角/交叉参数位移、未舍入分解残差和 float32 提交残差。分解只是同一固定头内的代数核对，不是移除交叉块后的实际模型端点，不支持因果归因。

`ALL24_UPDATE_DIAGNOSTICS.json`、`ALL2016_STATE_UPDATE_DIAGNOSTICS.json` 与 `ALL2016_RECORDED_TRANSITIONS.json` 报告归档响应/保持项梯度的大小、夹角、实际更新内积、投影及下一条记录的变化。最后一步与原生端点的比较单独标记，不能与相同后端的功能记录混同。

## 数值复现与边界

有效控制的三项加权求和登记两种等价 float64 求值顺序：显式左结合求和与 NumPy matmul。归档有效控制摘要必须精确匹配其中之一；未知摘要直接阻断，两种求值的数组还须在 1e-15 内一致。这只是兼容不同 BLAS 求和顺序，不改路由、参数、循环偏移、原生门槛或候选。不通过任意放宽哈希来接受记录。

C149 作为封存的先前审计凭据使用，不声称跨 NumPy 构建重跑较早的完整递归审计链。较早链接但不在七个输入内的原 ZIP 未重新打开。

归档梯度不是本轮独立重算的真导数；梯度内积与线性化残差不构成导数误差界、曲率界、因果解释或不可行性证明。文件内部一致性也不证明历史时序、非访问声明或原测量准确性。参数数量与优化几何仍是对照差异。

**C151 是归档审计，不产生新模型测量或训练候选；不关闭 LC2 或单折。** 即使将来训练全过，也仍需新的前瞻确认和严格隔离的排除输入评估。
