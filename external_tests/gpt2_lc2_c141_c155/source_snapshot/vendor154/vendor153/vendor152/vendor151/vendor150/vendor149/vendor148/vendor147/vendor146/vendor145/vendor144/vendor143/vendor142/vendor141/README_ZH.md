# C141 CPU：冻结C140的48态共享核局部确认

## 运行

下载 `C141_CPU_LAUNCHER_R1.py` 和 `C141_CPU_LAUNCHER_R1_BUNDLE.zip`。将启动器全文粘贴到Colab一个代码单元；提示时只上传这一份BUNDLE.zip，无需解压。源码放在配套ZIP，启动器保持轻量。无需GPU。

程序挂载Drive，按已固定路径和SHA256自动读取C132–C140九个原科学结果包。若原文件移动，可填写启动器顶部相应 `C132_ZIP` 至 `C140_ZIP` 的绝对路径；内容仍须匹配原哈希。

成功或失败都会封装一个结果总包，含源码、日志、输入绑定、冻结提案、逐态记录、未完成请求和报告；尝试备份到Drive并下载。工作进程上限50分钟，合成协议测试上限40分钟，固定HF依赖检查/安装单独计时。超时保持未完成，不缩小分母。

## 固定范围

C140第12步在36个训练态完整通过。本次冻结其控制向量、原V、原raw写入器、控制、归一化及特征公式，检验已知输入类中的新局部方向；不继续训练。

- 围绕原12个已知中心，各用范数0.125、0.375，每档两个全新固定种子方向，共48态，三个已训练输入类各16态。
- 制备使用原C132共享响应行空间的正交补投影，再归一到声明范数并提交float32。无新几何拟合、Jacobian、SVD、方程求解、制备修复、缩步或重抽。固定共享核不等于有限步长制备保证。
- 候选和设计先于新坐标生成封存；全部48坐标先于模型初始化封存；所有144个raw/C137/C140提案先于首次新写入端点测量封存。
- 原九包全文件哈希固定；对C140重算12步更新、432训练行和216端点的归档算术。此审计不独立验证归档梯度的真实性。
- 加载真实CPU GPT2后，重新取得全部36训练态的写前特征并重放144个已知制备/raw/C137/C140点。控制漂移会在新态模型测量前阻断。
- 全部48新态的制备点测量两轮，共96条；全部取得写前特征；三写入臂各两轮，共288个新写入端点。预计1309次模型前向。
- 制备失败保持失败并继续测量有限提案，强制其端点资格失败；不删除、替换或只报告有效子集。
- 两轮是同48态的重复测量，不是96个独立样本。

## 验收

沿用原门槛：响应0.002、KL0.005、读裕度0.05、写入位移半径20及原浮点容差。C140训练安全线0.00125只作描述，不替代原验收线。

`complete=true` 表示请求完整完成。`local_confirmation_passed=true` 还要求：48态两轮制备全部有效；冻结C140两轮完整门槛48/48；控制与重复一致。

raw和C137只是固定对照；即使它们通过，也不能替代C140的失败。没有训练、反传、头拟合、教师、回溯、在线修复、候选选择或部署。

## 结论边界

通过仅支持同一共享核制备族、已知训练中心附近的新局部方向确认，不支持新中心、排除输入、跨模型或长序列泛化。需要另行预登记隔离的排除输入协议；`LC2_closed=false`、`LC2_single_fold_passed=false`。

状态ID和种子相对本次绑定注册表为新；坐标哈希与九原包显式坐标哈希及已绑定训练/端点比对。未建立全项目历史穷尽、独立时序或全局非访问证书。所有C141测量态在本轮后均已暴露；若未来据此适配，应记为开发数据，不得重新冒充未见确认。
