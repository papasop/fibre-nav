# C147：C146 最坏响应训练只读审计（CPU）

将 `C147_CPU_LAUNCHER.py` 全文粘贴到 Colab。提示时只上传一份 `C147_CPU_LAUNCHER_BUNDLE.zip`，无需解压。启动器不内嵌源码；不需要 GPU，不安装 Torch 或 Hugging Face 依赖。

## 固定输入

按固定路径和 SHA256 定位原 C146、C145、C143 三份科学结果包，均只读。优先使用 Drive 恢复目录，同时兼容 C146 和 C145 日志中的原始 `/content` 会话路径。文件已移动时可填写对应 `C146_ZIP`、`C145_ZIP`、`C143_ZIP` 的绝对路径，仍必须匹配原哈希。

三份原ZIP全部重哈希。C144、C140、C141、C142的固定引用会核对，但本轮不重新打开或重哈希这四份原ZIP。程序只执行随本包交付并固定哈希的审计代码，不执行科学结果ZIP内的源码。

## 核对范围

1. 可信源码清单、实际冻结 writer/control/basis 张量，以及 C143/C146 全84态坐标和完整3211维特征逐行绑定。
2. C145 原包中的756个提案、1512条门槛和归档梯度参与的代数；这部分使用交付的固定 C145 审计读取器。
3. C146 初始化必须为原 C143 第12步，Adam一、二阶矩为零。不得替换为 C145 探测点。
4. C146 全336条原生重放、全84态零控制和全84态非零控制的归档功能/原生一致性。
5. 全12步、1008条训练记录：独立表达响应超额损失和保护项、精确max并列权重、逐态贡献、梯度裁剪、Adam一二阶矩、控制盒投影与实际更新。
6. 最终头必须为第12步实际张量；重算252个封存提案，核对冻结记录；重算三臂、全84态、两轮504条最终门槛及获救/破坏配对。

全程不加载模型、不进行新前向或反传、不训练或拟合、不求解方程、不做新Jacobian/SVD、不挑检查点或日程，不改写C146原判定。原响应0.002、KL0.005、读裕度0.05和位移预算保持固定。

## 诊断输出

- `ALL12_UPDATE_AND_MAXIMIZER_DIAGNOSTICS.json`：各步最坏响应、最大损失态、响应/保护梯度规模和内积、裁剪、投影及真实控制位移。
- `ALL1008_STATE_TRAINING_DIAGNOSTICS.json`：全84态逐步有符号响应、活跃响应坐标、每坐标预算裕量、损失、权重、梯度贡献与下一记录间的预测残差。
- `ALL84_STATE_HISTORIES_AND_FINAL_GATES.json`：各态完整训练历史和最终原生门槛，保留全部失败态。
- `ALL12_RECORDED_TRANSITIONS.json`：11个训练前向之间的转移，以及第12次更新到最终原生端点的单独比较。
- `RECOMPUTED_NATIVE_SUMMARIES.json`、`RECOMPUTED_PAIRED_RESULTS.json` 和 `REPORT_ZH.md`：全分组原生门槛和配对结果。

工作进程上限20分钟，协议合成测试上限40分钟，分别计时，每30秒输出心跳。无论完成、异常或超时，均封装一个结果ZIP，包含报告、明细、日志与源码，备份Drive并尝试下载。

## 解释边界

归档梯度向量是算术输入，未独立重算为真实导数。训练阶段的功能前向响应计数不是新的原生验收；最后一步到原生端点的比较明确标注数据来源差异。

最大值切换、梯度夹角及一阶预测残差仅为描述；不能单独证明导数错误、步长过大、控制结构不足、收敛、驻点或不可行。投影和float32提交、非光滑max与有限步非线性均可能影响解释。审计不自动选出更小步长、新结构或最佳检查点。

归档一致性不能独立证明历史测量准确性、时序或未访问。没有新状态、独立确认或排除输入评估。C146失败判定保留，LC2与单折均未闭合。合成验证不冒充原始科学结果包的实际审计。
