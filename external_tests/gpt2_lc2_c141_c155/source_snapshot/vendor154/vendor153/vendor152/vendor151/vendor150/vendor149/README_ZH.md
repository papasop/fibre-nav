# C149：C148只读路由与控制分化审计（CPU）

本轮核对C148归档的一致性，并量化为什么两条分支可能拥有不同的控制，却得到相同的通过数。所有诊断都是描述性的；不预设“路由无效”“梯度冲突”或“全局控制不可行”。

## 启动

将 `C149_CPU_LAUNCHER.py` 全文粘贴到 Colab 一个单元执行，提示时上传一份 `C149_CPU_LAUNCHER_BUNDLE.zip`，无需解压。启动器不嵌入科学源码。

程序挂载 Drive 并自动定位原 C148、C147、C146、C145、C143 五个结果ZIP，逐一匹配固定SHA256。也可在启动器顶部填写它们的绝对路径；路径可变，原内容必须匹配。配套BUNDLE是源码包，不要用科学结果ZIP代替上传。

只依赖NumPy，不加载Torch、Transformers或GPT-2，不下载模型。审计工作进程上限20分钟；合成协议测试另有40分钟上限。自测用解析和记录重放的测试替身构造历史归档，不构成模型科学结果。最终只有一个结果总包，包含报告、全部诊断、日志和交付源码，自动备份Drive并下载。失败、中断或超时也封装失败结果。

## 固定核对范围

- 五个原始结果ZIP及交付源文件身份；C147归档算术重新核对，绑定实际C146最终头。
- 全部84态与三类训练成员身份、原始坐标及完整3211维特征、V和原冻结头。
- C148训练侧归一化、预登记种子与8轮Lloyd构造的算术重放，仅核对原冻结路由；不拟合或选择另一套路由。
- 原生预检336记录、零控制功能比较84记录、两臂初始功能比较168记录。
- 双臂各12步共24次更新、2016条训练记录；独立核对损失、路由梯度拉回、最坏态加权、Adam动量与系数投影。
- 两个实际最终头必须等于各自固定第12步；重算全部336个float32提案和672条原生端点门槛。
- 全部通过、失败、救回和破坏均保留；不更改原门槛，不挑选分支或检查点，不部署。

## 主要诊断文件

|文件|内容|
|---|---|
|`ROUTING_WEIGHT_DIAGNOSTICS.json`|各控制器权重的跨态范围、熵、软有效数量及硬分配数量|
|`ALL12_PAIRED_UPDATE_DIAGNOSTICS.json`|每步局部头分化、归档梯度夹角、梯度与实际更新的符号一致比例、投影数量|
|`FINAL_CONTROL_AND_PROPOSAL_SEPARATION.json`|局部头两两差异、有效控制与全局控制之差、实际float32提案差异及门槛分歧|
|`ALL84_ROUTING_CONTROL_AND_ENDPOINT_DIAGNOSTICS.json`|全84态的权重、有效控制、四臂有符号响应、逐坐标预算裕度和失败门槛|
|`ALL2016_ARCHIVED_TRAINING_DIAGNOSTICS.json`|全部训练记录与归档梯度对实际控制位移的线性描述|
|`RECOMPUTED_NATIVE_SUMMARIES.json`、`RECOMPUTED_PAIRED_RESULTS.json`|原生门槛及各臂救回/破坏配对的重算结果|

这些数值不设置“足够分化”阈值。相同硬分配不等于相同软权重；不同控制器可能在混合时抵消；float64控制有差异也可能在float32提交后产生相同提案。因此分别报告上述层次。

## 证据边界

归档有效控制梯度仅作为未独立验证的导数输入；算术吻合不能证明梯度是真导数。此轮不重放模型、不测新端点，不证明时序、留出数据非访问、测量准确性、曲率界、收敛、可行性/不可行性或失败因果。较早关联C144/C140/C141/C142原ZIP未重新打开。

C148的36参数全局控制与108参数路由控制仍存在参数数目和优化几何差异；本审计不建立路由优越性。0.125是控制系数边界，不是低曲率邻域半径。没有新头拟合、路由候选、模型前向、反传、训练、Jacobian、SVD或线性求解。LC2及单折判定始终为false。
