# C134：固定写入路径实测（CPU）

把 `C134_CPU_LAUNCHER.py` 全文粘贴到 Colab 单个代码单元运行。提示时只上传一份 `C134_CPU_LAUNCHER_BUNDLE.zip`，无需解压。启动器不嵌入科学源码。

程序自动挂载 Drive，读取固定原 C132 与 C133 科学结果包；也可填写 `C132_ZIP`、`C133_ZIP` 的绝对路径，内容仍须匹配固定 SHA256。`SOURCE_ZIP` 只接受配套 BUNDLE。

## 固定设计

- 6个 C132 几何构造中心，均为历史已见输入类训练态。另6个探测中心只核对归档，不增加模型测量。
- 3臂：原冻结 raw 写入、共享响应投影、投影并保持共同一阶读出。
- 7个固定步长：`0, 1/64, 1/16, 1/4, 1/2, 3/4, 1`，两轮共252条测量请求。
- 路径从制备坐标连到 C132 实际 float32 提交端点。先用float64插值，再float32提交；0和1保持原始坐标字节。所有126个点的结果在加载模型前封存。
- 起点使用制备态门槛；所有正步长使用同一个最终写入目标及原固定门槛。不因小步长尚未翻转内容而改写目标或删掉失败记录。
- 不可用臂保留全部空请求，不选择可用臂或步长部署。

## 先核对，再新测量

在模型加载前核对 C132/C133 整包哈希和原交付源码身份，独立重算 C133 的36条局部分解、24条对照和完整组件数组。

加载固定 revision 的 GPT-2、原 LoRA-A/LoRA-B 坐标图，CPU float32。先重放6个制备态和18个可用完整端点：完整22维观测绝对误差需≤0.0002、KL差≤0.000005，坐标身份及所有原门槛判定一致。重放不一致则停止后续路径测量。

全部点新测后再核对已知起终点与两轮重复。如后续发生漂移，保留252条请求，但取消路径机制解释资格，不把运行完成写成机制确认。

## 输出与解释边界

使用本次新测制备态观测作为基准，计算：

`余项(alpha) = 新测观测(alpha) - 新测写前观测 - C132局部Jacobian × 实际float32位移`。

保存响应6坐标与精确读出4坐标的完整向量；其他读出与KL仍按门槛核对，不套用不存在的导数。报告名义一阶作用、实际一阶作用、线性舍入影响、有限分数斜率以及余项/alpha²。alpha=0不计算斜率或除以alpha。

“首次采样余项越过响应预算”仅为固定网格的描述，不是真正的连续起点，不选作部署步长。有限分数斜率不是精确导数；余项不能唯一归因为曲率、AD错误或前向数值误差，未建立前向准确性界。

所有请求、失败、不可用项、重复误差、源码、日志、报告、逐点组件与清单统一封装一个结果ZIP，自动备份Drive并下载。部分失败保留进度和未完成请求数。

无新反传、Jacobian、SVD、训练、拟合、方程求解、教师或响应修复；没有新态、排除输入测评、候选选择或LC2通过声明。工作进程上限50分钟，CPU无需GPU。
