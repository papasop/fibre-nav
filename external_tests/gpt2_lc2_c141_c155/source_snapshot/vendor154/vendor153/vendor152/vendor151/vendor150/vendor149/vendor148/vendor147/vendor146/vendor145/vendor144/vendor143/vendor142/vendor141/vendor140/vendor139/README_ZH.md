# C139 CPU：共享核制备诊断

## 运行

1. 下载 `C139_CPU_LAUNCHER.py` 和 `C139_CPU_LAUNCHER_BUNDLE.zip`。
2. 将启动器全文粘贴到 Colab 的一个代码单元运行。使用 CPU 即可。
3. 提示上传时只选择这一份 BUNDLE.zip；无需解压，不选任何历史结果包。启动器不内嵌实验源码。
4. 程序挂载 Drive，按已固定的绝对路径和 SHA256 寻找 C132–C138 七个原科学结果包。若路径移动，可在启动器顶部填写对应 `C132_ZIP` 至 `C138_ZIP` 的绝对路径，文件内容仍须匹配。
5. 成功或中断都会生成一个结果总包，包含源码、日志、输入绑定、逐态记录和未完成请求数；自动备份到 Drive 并尝试下载。

## 这次检验什么

C138 的 24 态中有 22 个制备态本身未通过门槛，因此需要分开报告制备失败和有效制备上的写入失败。C139 首先从原包重算全部制备门槛、96 条端点和提案绑定；不会改写 C138 判定。

然后对相同的 24 个已暴露方向做固定干预：保持原父中心、随机种子和 L2 范数，只把扰动投影到原 C132 固定共享响应行空间的正交补，再归一到原声明范数。无新 Jacobian/SVD/拟合/求解，亦无制备修复、缩步、重抽或挑态。若方向塌缩或坐标碰撞，停止并保留未完成请求。

投影不是有限步长制备保证。程序实测全部 24 个核制备点两轮，并在所有点上执行原 raw 和冻结 C137 第24步写入器，两轮共 96 个端点。制备失败仍计入请求、继续测量有限提案，并强制端点资格失败。全部新提案在首次新写入端点测量前封存。

已知控制先行：12 个原父中心的特征和36 个原生点、24 个 C138 原制备点重放。控制漂移阻断后续核制备测量。预期总计517次真实 GPT-2 CPU 前向；工作进程上限50分钟。依赖核对、固定版本安装和合成测试单独计时。

## 如何读结论

- `complete=true` 仅表示固定诊断全部完成。
- `kernel_preparations_all24_passed=true` 要求两轮24/24制备通过且重复一致。
- `frozen_writer_all24_development_gates_passed=true` 还要求冻结 C137 在全部24态两轮完整通过。
- 无论上述数值如何，都不选候选、不部署，不声称新的独立确认或排除输入泛化，`LC2_closed=false`、`LC2_single_fold_passed=false`。
- 制备失败：停止这组固定共享核制备方案；制备全过但写入失败：先解决开发域写入问题；全部开发门槛通过：另行预登记新的未见局部确认，之后仍需独立的排除输入协议。

重点结果：`C138_PREPARATION_AND_ENDPOINT_AUDIT.json`、`KERNEL_PREPARATION_SUMMARIES.json`、`PAIRED_PREPARATIONS.json`、`ENDPOINT_SUMMARIES.json`、`PAIRED_VS_RAW.json` 和 `SUMMARY.json`。

## 交付验证范围

交付目录的 `LOCAL_VALIDATION.json` 与 `LOCAL_TEST_LOG.txt` 记录本地合成验证。全维坐标、归档语义、固定阶段和请求计数可本地检验；真实 GPT-2 模型执行和七个原科学包的核对须在持有原包的 Colab CPU 中完成，不能用合成测试替代。
